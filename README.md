# Глянец — запись на детейлинг в Telegram и MAX

[![CI](https://github.com/automatorr192-dev/glyanets/actions/workflows/ci.yml/badge.svg)](https://github.com/automatorr192-dev/glyanets/actions/workflows/ci.yml)

Мини-приложение и бот детейлинг-студии: клиент выбирает услугу и класс машины, видит цену
и свободное время, записывается в пару касаний, вносит предоплату прямо в Telegram, за два
часа до визита получает напоминание с кнопками «Перенести» и «Отменить», а пока машина в
работе — следит за этапами. Вопрос можно просто написать боту: «сколько стоит керамика на
кроссовер, есть время в субботу?» — ИИ-администратор посчитает, найдёт время и запишет.

**Демо мини-аппа → https://automatorr192-dev.github.io/glyanets/** (открывается и в браузере;
это демо-режим без сервера, записи живут в браузере). Живой сервер с ботом — после деплоя.

## Что закрывает

Студия теряет клиентов на переписке «а сколько стоит» и «а когда свободно», а время — на
неявках. Здесь цена и свободные окна видны сразу, запись подтверждается предоплатой,
напоминание приходит само, а вопросы в чате закрывает ИИ-администратор. Администратору
студии в Telegram приходит каждая запись, перенос, отмена и просьба «позовите человека».

## Что умеет

- Каталог с ценой по кузову S / M / L, скидка 10% за комплекс «полировка + керамика».
- Запись в три шага; свободное время на две недели вперёд по частям дня, по числу боксов.
- Перенос и отмена — в мини-аппе и кнопками из напоминания.
- Предоплата 20% по СБП или картой через RollyPay — ссылка работает и в мини-аппе, и в чате
  Telegram и MAX; запись подтверждает подписанное уведомление об оплате, а не возврат клиента
  со страницы оплаты. Неоплаченная бронь держит время
  15 минут и освобождается сама.
- Напоминание за 2 часа до визита — в тот мессенджер, где клиент записывался.
- ИИ-администратор в чате бота: цены, свободное время, запись, «мои записи», отмена, позвать
  человека. Тот же администратор работает в MAX.
- «Мои записи» и живой статус работы по этапам.

## Как устроено

```
Telegram ── мини-апп (Vite + React) ──┐
          └ бот: чат, напоминания,     │  X-Init-Data (подпись Telegram)
            предоплата ────────────────┤
MAX ───── бот: чат, напоминания ───────┤
                                       ▼
                    app.py (FastAPI) ── schedule.py: цена, начала, готовность
                                    │   из catalog.json — того же, что у мини-аппа
                                    ├── concierge.py: ИИ-администратор (OpenRouter)
                                    └── db.py ── Postgres: записи по боксам,
                                                 EXCLUDE против пересечений
```

Один контейнер: FastAPI отдаёт собранный мини-апп, API записи и держит обоих ботов.

**Цену и время считает сервер.** С телефона приходят только выбранные услуги, класс машины,
день и время. Цены, скидка, длительность и «когда будет готово» — по `catalog.json`, из
которого читает и мини-апп: правила не разъедутся, а сумму с фронта подделать нельзя.

**Двойную запись не пускает база.** Два клиента жмут «Записаться» на одно время в одну
секунду — оба запроса успевают увидеть свободный бокс. Поэтому код только выбирает бокс, а
на Postgres стоит ограничение `EXCLUDE USING gist (box WITH =, tstzrange(start_at,
ready_at) WITH &&) WHERE (status <> 'cancelled')`: вторая запись получает отказ базы, и код
пробует следующий бокс. Тест на гонку гоняется в CI на настоящем Postgres.

**Кто записывается — из подписи Telegram.** Каждый запрос мини-аппа несёт `initData`,
подпись сверяется на боттокене; id пользователя берётся оттуда, а не из тела запроса.
Чужую запись не увидеть, не перенести и не отменить.

**Московские часы где угодно.** Студия в Москве, а телефон клиента может жить в любом поясе.
Первая проверка на машине в UTC+8 показала: мини-апп собирал «09:00» по местному времени и
отказывал в записи как в прошедшей. Теперь в живом режиме мини-апп считает и показывает
время по Москве, а на сервер уходят только строки «день» и «время».

## ИИ-администратор

Цикл с инструментами: модель решает, что ей нужно, код исполняет и возвращает результат.

| Инструмент | Что делает |
|---|---|
| `price` | цена и длительность по каталогу |
| `free_times` | свободные начала на дату по боксам |
| `book` | запись — только после согласия, с телефоном |
| `my_bookings` | предстоящие записи клиента |
| `cancel_booking` | отмена своей записи |
| `handoff` | позвать живого администратора с выжимкой |

- **Инструменты привязаны к клиенту кодом.** У модели нет параметра «id пользователя»:
  ни ошибка, ни инъекция в сообщении не дотянется до чужой записи.
- **Цены и время только из инструментов.** Скидок, которых нет в каталоге, модель не обещает.
- **Повторное «да» — та же запись.** На первой живой проверке модель записала клиента на
  «давайте на 10:00, телефон…», а на следующее «да» записала ещё раз — второй бокс занят
  впустую. Теперь `book` с тем же временем и услугами возвращает существующую запись.
- Слова клиента идут в блоке со случайной меткой; длина ответа ограничена; после шести
  шагов без ответа разговор уходит администратору.

## Запуск

Демо мини-аппа без сервера (как на Pages):

```bash
npm ci
npm run dev       # http://localhost:5173
```

Всё вместе — сервер, мини-апп в живом режиме, боты и Postgres:

```bash
cp .env.example .env    # BOT_TOKEN, ADMIN_CHAT_ID, OPENROUTER_API_KEY, по желанию ключи RollyPay и MAX_BOT_TOKEN
docker compose up --build
```

Без Docker — тот же код на sqlite:

```bash
pip install -r requirements.txt -r requirements-dev.txt
VITE_API=1 npm run build
uvicorn app:app --reload
pytest -q
```

Мини-апп открывается в Telegram по https-адресу сервера: его же ставят в `WEBAPP_URL`.
